# Idaho dashboard reporting accuracy repair

Owner requested direct correction of dashboard discrepancies. Separate independent branch; no Scout branches modified.

Scope: presentation only. Summary counts, classifications and reported valuations now use the exact filtered rows used for paging and CSV. Evidence breakdown separates issued, application received, planning and unverified, and explicitly labels the total published dataset. Applications are not presumed pending. Mountain calendar-date ranges reject invalid/future dates, while All dates / Any score still exposes all published identities. Source cards show per-source newly observed records only when comparable, not a statewide issued count. Nonmatching snapshot timestamps and HTTP errors fail visibly. Existing score values, threshold options, records, qualification, builder rankings and RSS are untouched. The default minimum score is now Any score (rather than Score 30+), because the latter hid all 143 single-family records in the 30-calendar-day window ending Nov 26, 2026. This is a display default only, not a scoring-policy or qualification change. Users can still explicitly select Score 30+. No changes to collector activation or historical recovery.

Release gate: confirm recovery of failed production run #396 via run #397 or subsequent accepted run; exact candidate/current-main CI; compare data/ and public/data and feeds tree fingerprints, repeat browser checks on real snapshot desktop/mobile; verify final served files against deployment archive before further production releases. Safe rollback procedure: owner-approved revert of this presentation-only commit after baseline revalidation; no historical data deletion. This change cannot repair upstream Eagle/Nampa access, Post Falls freshness or missing city coverage.
